# PRbot 設計

## 目的

他プロジェクトのドキュメント typo を、小さく・礼儀正しく・断られても相手に負担をかけない形で直す PR を、半自動で準備する。

## 方式の比較

| 方式 | 利点 | 問題点 | 採用 |
|---|---|---|---|
| 全自動で大量提出 | 数は出せる | スパム扱い・荒らし判定の危険、相手の文化を無視する | しない |
| 半自動（候補+diff自動、提出は本人確認） | 質を保てる、1件ずつ相手に合わせられる | 手間は残る | **採用** |
| 完全手動 | 最も安全 | 探索と diff 作成が毎回手作業 | 補助として残す |

## 安全の既定値

- 対象ファイルはドキュメントだけ（`.md/.mdx/.rst/.txt/.adoc`）。コード・設定・翻訳ファイルは対象外
- 書き換えない場所：コードフェンス内、インラインコード、URL
- 辞書は「誤りが一意に確定する」置換だけ。文脈依存の修正（助詞、表記ゆれ、固有名詞）は辞書に入れない
- 1 PR の上限：3ファイル・20件まで（`is_safe_change`）。超えたら分割するか候補を捨てる
- 提出ガード：`bot/github_client.py` は既定で提出を拒否し、スターターキットでは自動提出そのものを実装しない
- 同じ相手への連続提出はしない。まず 1 件出して反応を見る

## 相手への配慮

- CONTRIBUTING・PR テンプレート・行動規範を先に読む。typo PR を歓迎していないプロジェクトには出さない
- 似た修正の PR が既に open でないか検索する
- PR 本文ではツールで下準備したことを隠さない（テンプレートに明記）
- 断られたら議論しない。理由が書かれていれば次の候補選びに反映する
